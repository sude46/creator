# 收藏接口与设计

## 接口契约

所有入口要求 Session 登录，PUT/DELETE 要求真实 CSRF token。关系用户只能来自当前 Actor，不接受 userId/ownerId 作为操作目标。管理员与普通用户采用同样的本人收藏边界，没有管理他人收藏的入口。

| 接口 | 行为 |
| --- | --- |
| `PUT /api/favorites/{videoId}` | 收藏当前公开可见视频；新增及重复收藏均返回 204，无请求体 |
| `DELETE /api/favorites/{videoId}` | 取消本人收藏；不存在也返回 204，无请求体 |
| `GET /api/favorites/{videoId}` | 返回本人关系状态 `{favorited:true}`，不返回作品信息 |
| `GET /api/favorites?page=1&size=20` | 本人收藏列表 `{items,total,page,size}` |

videoId 必须为正整数。列表每项为 `{videoId,createdAt,available,video}`，videoId 为字符串，createdAt 为 UTC 收藏时间。available=true 时 video 使用 [公开作品视图](public-media-api.md)；不可见时 available=false、video=null，只保留本人已有收藏标识及收藏时间，供显示占位和取消。不能从收藏接口取得审核原因、对象键或媒体 URL。

列表按收藏关系 ID 倒序，分页 1～1000，每页 1～50，默认 20。total 包含当前不可用的本人收藏，分页不会因内容被隐藏而补查更多历史。重复收藏不更新时间或排序；取消后再次收藏产生新记录和新时间。收藏状态查询只查询本人关系，允许在视频下架、软删除或不存在时返回 true/false，不披露目标作品是否存在或当前内容。

## 业务和安全规则

添加先复核有效账号及角色快照，再使用与首页/详情/播放授权一致的公开查询条件校验目标，最后插入唯一关系。不存在、未审核、未发布、作者停用、删除/封禁、处理代次或资源不完整均返回 404；作者和管理员也不能收藏自己的私有草稿。分类停用不撤销现有审核批准，所以已发布作品仍允许收藏。

同一用户/视频唯一约束负责并发去重，只把 DuplicateKeyException 视为重复成功，其他数据库错误不会伪造成功。重复添加也先检查当前公开状态：原收藏仍在但作品已经下架时返回 404，不能以“此前收藏过”绕过可见性。

取消只删除 Actor 对应关系，不先查询视频，不要求作品仍公开；因此被封禁或软删除的作品仍可取消。状态和列表也不能读取别人的关系；角色变化或账号禁用使内部用例同样拒绝访问。HTTP 过滤链与用例共同校验，不能只靠前端隐藏按钮。

## 分层、事务与并发

FavoriteController → FavoriteService → FavoriteRepository/MyBatis；公开内容经现有 VideoQueryRepository 协作，领域 Favorite/FavoriteItem 不依赖 HTTP 或持久化框架。列表先读取最多 50 条本人关系，再一次 IN 批量查询当前可见内容，最后读取本人总数；加上账号复核为最多四次数据库查询，空页跳过内容查询。不逐条查询、签名或 HEAD 对象，不引入 Redis。

列表在只读事务中投影，MySQL 当前隔离配置下使用同一事务快照。响应可能在下架前已经读取，不能宣称立即撤回所有在途响应。播放仍须重新走媒体授权，收藏存在或列表返回内容不能当作播放权限。

添加/取消使用 5 秒短事务，不访问外部存储、队列或网络。账号有效性检查不加账号写锁，也不主动锁目标作品；并发停用或下架时允许已经通过检查的请求留下关系，下一次查询重新按当前公开状态隐藏内容。这是原 L13 的一致性取舍，不承诺“下架瞬间没有新增关系”。关系插入的外键会产生数据库自身的引用检查锁，不能宣称完全无锁。

并发 PUT 在唯一索引下收敛为一条关系；PUT 与 DELETE 并发后的结果取决于数据库执行顺序，客户端需读取本人关系状态，不作无条件的最后一次点击顺序保证。超时或提交结果未知时先 GET 状态；可重复 PUT/DELETE，但不进行无界自动重试。

关系变化不写 operation_log：收藏是用户偏好，首版没有逐次偏好审计需求。封禁/审核等治理审计不受影响。插入或删除异常时事务回滚，没有外部副作用或额外补偿任务；需要偏好变更审计时应另行确定范围。

## 持久化与限制

V10 追加 video_favorite，含自增 ID、user_id、video_id、created_at；唯一 `(user_id,video_id)`、分页索引 `(user_id,id)`、账号和作品外键。软删除保留关系以显示不可用占位；未来物理资源回收/账号删除需要显式处理关联，当前没有物理删除作品接口。自动化测试在删除作品/账号前清理收藏关系，不通过关闭外键绕过约束。

首版没有收藏数量配额、缓存或热门排行；分页与 IN 上限不等于总存储容量已受限，长期关系增长和 COUNT 成本需按实际数据测量。没有新增配置或依赖，前端列表和按钮尚未接入。

缺身份/账号失效返回 401，缺或错误 CSRF 返回 403，不能收藏的目标返回 404，无效 ID/页码返回 400；数据库失败或锁超时返回 503。取消不存在关系返回 204。SQL 参数绑定，不通过调用者输入拼接 IN 值。
