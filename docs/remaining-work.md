## 5. 通知专项改动清单

| ID | 问题 | 优先级 | 说明 |
| --- | --- | --- | --- |
| N-01 | 单条通知不会标记已读 | 高 | `NotificationsView.vue` 只调用 `list`/`unread`；`notificationApi.read(id)` 已定义但未被调用。只有“全部标为已读”会调用 `read-all`。 |
| N-02 | 导航缺少未读徽标 | 高 | 只有进入通知页才看到未读数；需要在登录后和路由切换时拉取 `/api/notifications/unread`。 |
| N-03 | 单条已读/未读筛选/类型筛选/删除归档/清空已读 | 中 | 当前只有分页和全部已读。 |
| N-04 | 治理类通知缺失 | 中 | 管理员下架/封禁不通知作者；举报处理结果不通知举报人。新增类型需迁移放开 `notification.type` 的 CHECK 约束。 |
| N-05 | 通知聚合与防刷 | 中 | 每条评论、每次重新关注都会生成通知，可能刷屏或用于骚扰。 |
| N-06 | 通知链接失效 | 中 | 作品删除、下架或评论删除后，旧通知链接可能 404 或无权访问。 |
| N-07 | 通知保留期与清理 | 低 | `notification` 表无 TTL，长期运行会无限增长。 |
| N-08 | 通知写入与业务事务耦合 | 低 | 评论/关注/审核在业务事务内同步写通知；通知失败可能影响主操作，后续应走 outbox 或异步事件。 |
| N-09 | 通知渠道 | 低 | 只有站内通知，没有邮件、浏览器推送、WebSocket/SSE 实时更新和免打扰设置。 |
