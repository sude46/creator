# 帧间：项目案例

## 1. 一句话

帧间是一个面向视频创作者的 UGC 平台原型，覆盖上传、转码、HLS 播放、审核发布、评论互动、举报申诉和账号安全。

## 2. 背景

视频 UGC 产品的难点通常不在“把视频放上网页”，而在完整链路：

- 大文件上传如何断点续传
- FFmpeg 处理如何异步、可恢复
- 私有视频如何安全播放
- 审核、发布、封禁如何避免状态错乱
- 评论、通知、举报、申诉如何形成治理闭环
- 密码泄漏后如何让旧设备立即失效

项目目标是用一个可运行的全栈系统把这些链路串起来，而不是只做静态页面或单点 Demo。

## 3. 功能范围

### 公开侧

- 首页、分类、标签、搜索、搜索建议
- 竖屏 feed：最新、推荐、关注
- 视频详情、公开作者页、公开合集
- HLS 多码率播放，失败回退 MP4
- 5 种语言字幕，记忆开关和语言
- 评论、回复、点赞、@ 提醒、收藏、关注

### 创作者侧

- 草稿与作品信息
- 8 MiB 分片上传、逐片重试、文件指纹续传
- FFmpeg 处理状态、失败重试、取消处理
- 多码率 HLS、多语言字幕
- 送审、撤回、上下架、本人预览和下载
- 合集管理、数据看板

### 管理与治理

- 超级管理员 / 审核员 / 内容管理员
- 审核台、批量审核、封禁/解禁
- 举报处理、作品/评论申诉
- 分类、标签、用户、审计
- 历史作品 HLS 回填

### 账号安全

- Session 登录、CSRF、角色鉴权
- 自助改密、管理员重置
- 数据库设备会话、单设备退出、退出其他/全部设备
- 改密和管理员重置使目标账号全部会话失效

## 4. 架构

```text
Browser
  │
  ├── Nginx / Vue
  │
  └── Spring Boot API
        ├── MySQL
        ├── RabbitMQ
        ├── COS / MinIO
        └── 媒体任务
                 │
          Spring Boot Worker
                 ├── RabbitMQ
                 ├── MySQL
                 ├── COS / MinIO
                 └── FFmpeg
```

选择模块化单体，而不是微服务：

- 当前规模不需要服务发现、分布式事务和独立发布
- API/Worker 已通过独立进程隔离媒体处理
- 单体事务更适合审核、发布、上传绑定等一致性要求
- 后续拆分需要明确瓶颈和团队边界

后端按 `web → application → domain → infrastructure` 分层；Controller 不直接访问 Mapper/SDK，状态变更由 application 用例管理。

## 5. 最难的三件事

### 5.1 分片上传与失败补偿

问题：一次 PUT 200 MiB，断网只能从头传；对象存储、数据库、客户端响应任何一步失败都可能留下半状态。

方案：

- `upload_attempt` + `upload_chunk`
- 8 MiB 分片、逐片重试
- 文件指纹判断同一文件，支持未完成会话恢复
- 每片长度校验、幂等
- 完成后顺序组装、校验 MP4 头
- 对象存储写入不在数据库事务内
- 过期尝试和临时分片由维护任务清理
- 响应丢失时查询已绑定状态，不重复绑定

### 5.2 HLS 私有播放

问题：私有桶不能把永久分片地址给浏览器；MP4 单文件也没有多码率。

方案：

- Worker 生成最多 3 档 HLS
- 4 秒分片，playlist + TS 存私有对象存储
- 公开 master/media playlist
- media playlist 动态改写相对 TS 为短期签名 URL
- 前端 hls.js，失败回退 MP4
- 历史作品由管理员触发 HLS-only 回填，不改审核/发布状态

### 5.3 全设备会话失效

问题：改密只退当前设备，旧设备上的 Session 仍然有效。

方案：

- `user_account.session_version`
- `user_session` 设备注册表，只存 JSESSIONID 的 SHA-256 哈希
- 每个已登录请求校验账号、设备行、哈希、过期和版本
- 改密/管理员重置：版本 +1，撤销目标账号全部会话
- 设备列表、单设备退出、退出其他/全部设备
- 数据库不可用时鉴权失败关闭

## 6. 关键取舍

| 选择 | 原因 | 代价 |
| --- | --- | --- |
| 模块化单体 | 规模、事务一致性、交付效率 | 后续拆分成本 |
| Session + CSRF | Web 同源简单，HttpOnly | App 化需 Token |
| 私有桶 + 签名 | 不暴露对象键 | TTL 内不可立即撤销 |
| 同步通知 | 与业务事务一致 | 耦合，生产可走 outbox |
| LIKE 搜索 | 当前数据量足够 | 不是全文检索 |
| 字幕/头像 BLOB | 部署简单、事务一致 | 数据库膨胀 |
| 单 API 实例 | 当前演示规模 | 多实例需粘性会话/Spring Session |

## 7. AI 辅助开发

AI 在这个项目里主要做：

- 代码阅读和总结
- 迁移、测试和页面草稿
- 失败日志分析
- 文档整理
- diff 审查

人负责：

- 模块拆分和边界
- 数据模型和状态机
- 权限、事务、并发、幂等、失败补偿
- 最终测试和浏览器验证

真实例子：

- 搜索建议点击作者后结果为空：AI 生成的筛选同时带标题和作者，前端没清空标题；浏览器实测发现，修复后补验证。
- 分片上传开始返回 415：前端覆盖 Content-Type，后端媒体类型比较未兼容 charset；修复并补测试。
- 真实 MySQL 并发审核偶发死锁：单独复跑和全量复跑通过，记录为稳定性观察，不宣称已修复。

真实依赖：MySQL 8.4.3、RabbitMQ 4.0.5、FFmpeg、MinIO、COS

覆盖：

- 权限、所有权、CSRF、禁用账号
- 上传补偿、并发绑定、配额、租约
- 审核并发、发布状态
- 评论/通知/举报/申诉
- HLS、字幕、设备会话
- 真实对象存储签名和媒体处理

## 9. 当前边界

- 不是生产上线平台
- 无 DNS/ICP/TLS/COS CDN/备份/监控/容量验收
- 单 API 实例
- 无 2FA/忘记密码/邮箱验证/账号注销
- 搜索不是全文
- HLS 回填需手动触发
- 无 DRM/视频编辑/AI 生成/移动 App
- 通知同步写
- 字幕/头像 BLOB

## 10. 如果继续做

优先级：

1. 生产验收：DNS/TLS/COS CDN/备份/监控/容量
2. 账号安全：忘记密码/邮箱验证/2FA
3. 内容治理：关键词自动审核/用户禁言
4. 搜索：全文索引/搜索历史/相关度
5. 媒体：DRM、字幕对象存储、HLS 自动回填
