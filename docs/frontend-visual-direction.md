# 前端视觉方向

## 定位

平台是创作者管理作品的工作台，不是视频生成器。界面优先回答三个问题：作品现在处于哪一步、为什么停在这里、作者下一步要做什么。

## 当前方向

- 品牌名：帧间（Frame Room）。中文强调镜头之间的编辑感，英文用于导航和页面识别。
- 色彩：纸张灰白作为背景，墨绿色作为结构色，砖红作为动作和警示色，暗金只用于登录页的少量视觉标记。
- 形状：面板和卡片使用小圆角或直角，避免“所有内容都漂浮在圆角白卡里”。
- 媒体：作品列表使用 16:9 封面区，先为真实封面预留位置；没有封面时使用有编号、播放符号和色调区分的降级封面。
- 信息层级：状态标签只说明事实；“下一步”单独显示动作，避免作者从多个按钮里猜流程。

## 参考方法与工具

参考 [Vimeo 视频库](https://vimeo.com/features/video-library)、[Frame.io](https://frame.io/) 和 Descript 的媒体资产管理布局，参考 Linear、Notion 的状态和空状态表达，参考 Are.na 的克制排版。实现时优先使用本地 CSS 和项目已有 Element Plus 组件；图标可参考 [Lucide](https://lucide.dev/) 的开源图标规范，配色可用 [Radix Colors](https://www.radix-ui.com/colors) 校验对比度，避免未经许可的图片、字体和图标包进入仓库。

设计检查可以用 Figma 或 Penpot 做页面结构草图，用浏览器 DevTools 检查 390px、768px 和桌面宽度，用 Lighthouse 做基础可访问性和性能检查。外部素材只在确认许可证、尺寸和加载策略后接入，生产页面不依赖临时 CDN 图片。

## 去模板感检查

1. 每个页面必须有明确的工作任务和下一步动作。
2. 不用大面积渐变、无意义的装饰插画和泛化口号填充空白。
3. 空状态说明“为什么为空”和“点击后会发生什么”。
4. 状态由后端事实驱动，颜色只做辅助，文字必须可独立理解。
5. 真实封面、处理错误、审核原因和时间线优先于装饰卡片。

本轮首先落地创作中心列表。管理员审核、公开视频首页和播放页沿用同一套色彩、间距和状态表达，但会根据审核队列与观看任务单独设计信息架构。
